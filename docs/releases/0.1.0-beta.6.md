# Knitt 0.1.0-beta.6 — npm cloud release

The npm/npx installation remains the product installation route. No ZIP installation, plugin-directory publisher approval or graphical installer is required.

## Behavior

- `npx @tinchu0/knitt@latest plugin` configures detected coding agents and installs a durable runtime.
- The existing `/knit` skill handles account setup as well as continuation. Browser pairing does not enable uploads. Project preview, explicit cloud project selection and private sync consent remain separate.
- Approved supported histories import privately with retry-safe uploads. `/knit` can select local, personal cloud or accepted shared contexts. Recipients remain pinned to the selected version until choosing another.
- Reviewed publication, invitation acceptance and revocation use Knitt Cloud. Credentials and consent stay in the chosen installation directory, including custom `--home` setups.
- The npm package includes cloud CLI, account onboarding, sync and picker modules. It excludes the Cloudflare service implementation and runtime account data.

## Validation

- 107 source tests passed.
- Packaged lifecycle checks passed: npx bootstrap, persistent runtime, hook capture/recall, update, rollback, failed-update preservation and uninstall.
- The installed-tarball cloud test passed browser-session pairing approval, consent-before-upload, offline queue retry and deduplication, private history, reviewed publication and retry, explicit invitation acceptance, version pinning, third-account isolation, context/device revocation and logout. It uses three synthetic accounts and the actual Worker handler with a disposable local database.
- A fresh scoped read-only review found no release blocker.

These checks do not establish native Windows/macOS operation or the complete real-agent/two-account UI matrix. Those remain unverified. Ordinary ChatGPT and Claude web conversations are outside this coding-agent cloud release. Sync requires the running adapter or supported trusted hooks; stopping both stops uploads until the next run.

## Rollout

Publish the exact tested archive to `next`, verify the registry artifact and npx execution, then move `latest`. Existing data is retained. Use the installer rollback command with the same installation home to return to the previous runtime.
