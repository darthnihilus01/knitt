# Knitt beta.7 — recognizable conversations and direct continuation

Published release. User explicitly requested latest promotion after reviewing the remaining native app verification limits.

- `/knit` routes directly to recent project chats without account setup or cloud requests. Other sources provides the cloud picker; local continuation works offline.
- Root-aware source identity, native title precedence, explicit fallback labels, short previews, relative activity and host-sized native pages make selection recognizable. Claude summaries no longer overwrite titles. Codex names are read from the entire native session index, including rename entries.
- Selection freezes a private source snapshot, returns bounded recent messages and evidence immediately, and indexes older text in restartable batches. Transcript updates and SQLite WAL writes cannot change an already selected history. No checkpoint is invented.
- Private sync yields between batches, does not stall on incomplete JSONL records, and separates native ID collisions across roots while preserving the first source's existing cloud identity. Source metadata updates do not duplicate events.
- My contexts shows account, project consent, installation state, pending changes and last successful sync above private history. Metadata is reused in cloud choices and dashboard rows.
- ChatGPT history remains unavailable through the npm adapter; no manual export, browser extension or private host-tool bridge is introduced.

Verification is recorded in docs/superpowers/plans/2026-11-20-continuation-fixes.md. Automated MCP/fixture evidence is separate from real host UI checks. Cold filesystem snapshots can require a full file copy when copy-on-write is unavailable; warm selections reuse the immutable snapshot.
